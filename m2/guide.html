    Answers and why
    1. (0+1)*01(0+1)* + 1*0* = 1(0+1)* is false. The left side is every string: the strings containing 01, plus the strings with no 01, which are exactly 1*0*. The right side needs a leading 1, so ε and 0 are on the left but not on the right. The other two equations are true.
    2. False. In one step T becomes only XTX, X or ε. T ⇒* aba is true: T ⇒ XTX ⇒ aTX ⇒ aXX ⇒ abX ⇒ aba.
    3. 6. The grammar has three lines but two productions on each.
    4. 5: c, *, (, c, ). The four E nodes are interior nodes.
    5. statement → IF test THEN statement A, A → ELSE statement | ε. Leaving out the ε means every IF needs an ELSE. Factoring out only IF test changes the language.
    Quick checks that come up
    • Read the arrow. ⇒ is exactly one rule; ⇒* is zero or more rules.
    • Count alternatives, not lines. ε-rules count as productions.
    • Leaves = the symbols of the string (plus an ε leaf for each ε-rule used). Every parse tree of a string has the same leaves.
    • To disprove a regex equation, test the shortest strings first (ε, 0, 1, 01, 10). One string that is on one side but not the other is enough.

    Topic 1: Designing grammars and ambiguity

    Designing a CFG takes some creativity, but most grammars are built from a few patterns. Ambiguity is a property of a grammar, decided by counting parse trees.

    Design patterns

    PatternLanguageGrammar
    Union{0ⁿ1ⁿ} ∪ {1ⁿ0ⁿ}, n ≥ 0S → S₁ | S₂, S₁ → 0S₁1 | ε, S₂ → 1S₂0 | ε
    Concatenation of independent partsaⁿbⁿcᵐdᵐ, n, m ≥ 1S → AB, A → aAb | ab, B → cBd | cd
    Nesting, outside inaⁿbᵐcᵐdⁿ, n, m ≥ 1S → aSd | aBd, B → bBc | bc
    MirrorPalindromes over {a, b}S → aSa | bSb | a | b | ε
    Balance counterEqual a’s and b’s, nonemptyS → aB | bA, A → a | aS | bAA, B → b | bS | aBB
    Balance counterOne more b than aS → bB | aSS, B → ε | aS | bA, A → aB | bAA

    For the counter grammars, read each variable as a debt: A derives strings with one extra a, B strings with one extra b. Derivation of bab in the one-more-b grammar (rules 1, 4, 1, 3): S ⇒ bB ⇒ baS ⇒ babB ⇒ bab.

    Watch the boundaries
    • For aⁿbᵐcᵐdⁿ with n ≥ 1, S → aSd | B lets n be 0 (it generates bc). The base must be aBd.
    • S → 0S1 | 1S0 | ε is not {0ⁿ1ⁿ} ∪ {1ⁿ0ⁿ}: it mixes the patterns and generates 0101. Keep the parts in separate variables.

    Ambiguity

    A grammar is ambiguous if some string has two distinct leftmost derivations, or equivalently two distinct parse trees. Every derivable string has both a leftmost and a rightmost derivation, so that alone proves nothing.

    E → E + E | E * E | (E) | x | y | z gives x + y * z two trees, so it is ambiguous:

    S → AS | a | b, A → SS | ab gives abb two trees:

    Why it matters: a compiler gets meaning from the parse tree, so two trees mean two meanings (multiply first or add first). Sipser 2.8: “the girl touches the boy with the flower” can mean she uses the flower, or he has it. Sipser 2.27: in “if c then if c then s else s” the else can attach to either if (the dangling else).

    Removing ambiguity (when possible): give each precedence level its own variable, E → E + T | T, T → T * F | F, F → (E) | x | y | z, so * is always built below +.

    Topic 2: Simplifying grammars and Chomsky normal form

    Nullable variables and removing ε-rules

    • A is nullable if A → ε is a rule, or A → B₁…Bₙ with every Bᵢ nullable. Nothing else is. Equivalently, A ⇒* ε.
    • To remove ε-rules: for each rule, add every version with some nullable variables deleted (never an empty right side), then drop the ε-rules. Keep S → ε only if S itself was nullable.

    Worked example (lecture).

    OriginalAfter removing ε-rules
    S → AACDS → AACD | ACD | CD | AAC | AC | C
    A → aAb | εA → aAb | ab
    C → aC | aC → aC | a
    D → aDa | bDb | εD → aDa | bDb | aa | bb

    Nullable = {A, D}. C always produces an a, so C stays in every S-rule and S is not nullable (no S → ε). The new S → C is a unit rule; removing it gives S → … | aC | a.

    Chomsky normal form

    Every rule is A → BC or A → a, where B and C are not the start variable; S → ε is also allowed. Every context-free language has a CNF grammar (Sipser Theorem 2.9), and a CNF derivation of a string of length n ≥ 1 takes exactly 2n − 1 steps.

    1. Eliminate ε-rules.
    2. Eliminate unit rules (A → B): give A all of B’s right sides.
    3. Make each right side a single terminal or only variables: replace a terminal a inside a longer rule with a new Xₐ → a.
    4. Split rules with three or more variables into pairs.

    Worked example (lecture): S → ABC | c, A → BC | Aa | a, B → b, C → c. There are no ε-rules or unit rules. A → BC, A → a, B → b, C → c and S → c are already fine.

    RuleProblemCNF version
    A → AaTerminal in a long ruleA → AXₐ, Xₐ → a
    S → ABCThree variablesS → AD, D → BC (or S → DC, D → AB)

    Result: S → AD | c, D → BC, A → BC | AXₐ | a, B → b, C → c, Xₐ → a.

    Topic 3: Pushdown automata

    A PDA is an NFA with a stack. The stack gives unbounded memory, and PDAs recognize exactly the context-free languages.

    Formal definition

    A PDA is a 6-tuple M = (Q, Σ, Γ, δ, q₀, F): states, input alphabet, stack alphabet Γ, transition function, start state, accept states.

    δ: Q × Σ_ε × Γ_ε → P(Q × Γ_ε)

    Given a state, an input symbol (or ε) and a stack symbol (or ε), δ returns every possible (next state, symbol to push). The lecture writes the pair as P(Γ_ε × Q); the meaning is the same. On a diagram, a, b → c means read a, pop b, push c, and any of them may be ε.

    Example: M₁ for {0ⁿ1ⁿ | n ≥ 0}

    Q = {q₁, q₂, q₃, q₄}, Σ = {0, 1}, Γ = {0, $}, F = {q₁, q₄}. Push $, push a 0 per 0, pop a 0 per 1, and accept when $ shows again. $ marks the bottom because a PDA cannot test for an empty stack directly. q₁ accepts so that ε (n = 0) is in the language.

    Instantaneous descriptions (state, unread input, stack top first). If δ(q, a, Z) contains (p, β), then (q, aw, Zα) ⊢ (p, w, βα). On 0011:

    (q₁, 0011, ε) ⊢ (q₂, 0011, $) ⊢ (q₂, 011, 0$) ⊢ (q₂, 11, 00$)
             ⊢ (q₃, 1, 0$) ⊢ (q₃, ε, $) ⊢ (q₄, ε, ε)   accept

    001 is rejected: after its only 1 the stack is 0$, so ε, $ → ε never fires. 0 and 011 are rejected too; 01 and 000111 are accepted.

    Deterministic PDAs, shorthand, and power

    • A PDA is deterministic if no δ(q, a, Z) (a ∈ Σ ∪ {ε}) has more than one element, and whenever δ(q, ε, Z) is nonempty, δ(q, a, Z) is empty for every a ∈ Σ.
    • DPDAs recognize only some CFLs: {wwᴿ | w ∈ {a, b}*} needs a nondeterministic guess of the middle. So PDA ≠ DPDA, and “PDA” means nondeterministic unless stated.
    • Pushing several symbols: (r, xyz) ∈ δ(q, a, s) is shorthand for a chain through new states. Only the first move reads input; the remaining ε, ε → … moves push one symbol each.
    • Power: PDAs ≡ CFGs. Every regular language is context-free (a DFA is a PDA that ignores its stack), and {0ⁿ1ⁿ} shows the inclusion is strict.

    Topic 4: Predictive (LL(1)) parsing

    A predictive parser builds a leftmost derivation top down, choosing each production by looking at one input symbol. It needs a grammar with no left recursion and no common prefixes, plus FIRST and FOLLOW sets to fill its table.

    The idea in four moves

    The stack holds what the parser still expects to see, starting with E$. It repeats one of four moves:

    1. Nonterminal on top: look up M[top, lookahead] and replace the top with that production’s right side (an ε-rule just pops).
    2. Terminal on top that matches the lookahead: pop it and advance the input.
    3. $ on top and $ in the input: accept.
    4. Anything else (a blank cell, or a terminal that doesn’t match): error.

    It never backtracks: one lookahead symbol always decides which production to use. That is what the table and the FIRST/FOLLOW sets guarantee.

    Left recursion and left factoring

    • A grammar is left recursive if it has A → Aα. A recursive-descent parser for E → E + T | T calls E() again before reading any token, forever, until the stack overflows.
    • Remove it: A → Aα | β becomes A → βA′, A′ → αA′ | ε. So E → E + T | T becomes E → TE′, E′ → +TE′ | ε.
    • Left factoring: A → αβ₁ | αβ₂ becomes A → αA′, A′ → β₁ | β₂. The dangling-else grammar becomes stmt → if expr then stmt stmt′, stmt′ → else stmt | ε.
    E  → T E′
E′ → + T E′ | ε
T  → F T′
T′ → * F T′ | ε
F  → ( E ) | id

    FIRST and FOLLOW

    FIRST(α): terminals that can begin a string derived from α, plus ε if α ⇒* ε. FOLLOW(A): terminals that can appear immediately after A in some sentential form.

    1. $ ∈ FOLLOW(S) for the start symbol S.
    2. For A → αBβ, everything in FIRST(β) except ε is in FOLLOW(B).
    3. For A → αB, or A → αBβ with β ⇒* ε, everything in FOLLOW(A) is in FOLLOW(B).
    SymbolFIRSTFOLLOW
    E{(, id}{), $}
    E′{+, ε}{), $}
    T{(, id}{+, ), $}
    T′{*, ε}{+, ), $}
    F{(, id}{+, *, ), $}

    FOLLOW(T) gets + from FIRST(E′), and because E′ ⇒ ε it also gets FOLLOW(E) = {), $}. FOLLOW(F) gets * from FIRST(T′) and FOLLOW(T) because T′ ⇒ ε.

    The parsing table

    For each production A → α: add it to M[A, a] for every terminal a ∈ FIRST(α); if ε ∈ FIRST(α), also add it to M[A, b] for every b ∈ FOLLOW(A). Blank cells are errors. If any cell gets two productions, the grammar is not LL(1) (S → aA | aB puts both in M[S, a]; left factoring fixes it).

    LL(1): scan Left to right, build a Leftmost derivation, look 1 symbol ahead. LL(k) looks k symbols ahead.

    • T ⇒* T is true by zero steps; T ⇒ T is not.

    • CNF forbids the start variable on any right side.
    • FOLLOW sets never contain ε; FIRST sets can.
    • M₁ accepts ε because q₁ is an accept state.
